LUKORY (루코리) — 정적 웹사이트 패키지
버전 2.0 · 2026-10-09

1. 가장 먼저 할 일

이 ZIP의 압축을 풀고 index.html을 열면 사이트를 볼 수 있습니다.
실제로 웹에 공개하려면 index.html이 포함된 이 폴더의 내용 전체를 정적 호스팅에 업로드하세요.
별도의 빌드, npm 설치, 애플리케이션 서버, 데이터베이스 또는 API 키는 필요하지 않습니다.

반드시 index.html과 함께 styles.css, app.js, data.js, assets 폴더를 올려주세요.
index.html만 올리면 디자인, 이미지, 질문, 댓글 동작이 빠집니다.
index.html은 업로드할 폴더의 최상위에 있어야 합니다.

얼굴을 보고 각자 떠올린 인상과 이야기를 나누는 커뮤니티를 표현하는 조어입니다.

3. 실제로 동작하는 기능

- 메인 화면의 첫 질문에서 바로 시작하는 5단계 질문 흐름
- 첫 답변에 따라 문장이 달라지는 두 번째 질문
- 같은 선택지를 다른 문장으로 보여주는 질문 바꾸기
- 이전 질문으로 돌아가도 유지되는 답변
- 다섯 답변을 점수로 반영한 준비된 AI 얼굴 매칭
- 결과 얼굴과 선택한 답변 요약
- 제목과 닉네임을 입력해 데모 피드에 게시
- 분위기 필터: 전체 / 다정한 온기 / 조용한 신비 / 자유로운 감각 / 선명한 존재감
- 인기순 / 최신순 / 댓글 많은 순 정렬
- 얼굴 상세 화면, 첫인상 댓글 작성 및 내 댓글 삭제
- 좋아요 취소·재선택, 1인 1개 첫인상 투표 및 변경·취소
- 동일 브라우저에서 새로고침 후 게시물·댓글·반응 유지
- 모바일·태블릿·데스크톱 레이아웃, 키보드 초점 및 모달 Escape 닫기
- 모션 감소 설정을 따르는 애니메이션

4. 데모의 범위

이 패키지는 실제 AI 서비스와 연결되지 않은 프런트엔드 데모입니다.

질문:
AI가 미리 작성한 문항과 변형 문장을 사용합니다.
방문할 때마다 모델을 호출해 새로운 질문을 생성하지 않습니다.

얼굴:
실제로 AI로 제작한 여섯 개의 가상 인물 이미지를 포함합니다.
사용자의 답변마다 새 이미지를 생성하는 대신, 여섯 이미지 중 점수로 하나를 선택합니다.
따라서 다른 사용자가 같은 결과 이미지를 받을 수 있습니다.

커뮤니티:
초기 작성자·댓글·좋아요·투표 수는 모두 가상의 샘플입니다.
직접 입력한 게시물, 댓글, 반응은 현재 브라우저의 localStorage에만 저장됩니다.
다른 방문자나 다른 기기와 공유되지 않습니다. 사이트를 공개 호스팅하더라도
방문자 간 공유 기능이 저절로 생기지는 않습니다.
같은 브라우저의 같은 출처(프로토콜·호스트·포트)에서 PINTA v1을 사용한 경우,
LUKORY 저장 기록이 없으면 기존 데이터를 읽고, 다음 변경부터 새 이름으로 저장합니다.
다른 도메인이나 다른 브라우저에서는 localStorage가 별개이므로 이전 기록이 자동으로 옮겨지지 않습니다.
브라우저 저장 데이터 삭제, 비공개 모드 종료, 호스팅 주소 변경 등으로 기록이 사라지거나
다른 저장 영역으로 보일 수 있습니다. 저장이 금지되거나 꽉 찬 환경에서는 현재 페이지에서만 동작합니다.
데모 한도는 브라우저당 게시물 48개, 얼굴당 추가 댓글 100개입니다.

화면에도 'DEMO', '샘플 커뮤니티', '이 기기에만 저장' 안내를 포함했습니다.

5. 공개 호스팅 방법

A. Cloudflare Pages Direct Upload

Cloudflare의 Workers & Pages에서 Pages의 Direct Upload 방식으로 프로젝트를 만듭니다.
이 ZIP 또는 압축을 푼 사이트 폴더를 올립니다. index.html이 최상위인지 확인하세요.
업로드가 완료되면 제공되는 주소로 외부에서 접속할 수 있습니다.
코드 변경 후에는 같은 프로젝트에 수정된 파일 전체를 다시 배포합니다.

공식 안내:
https://developers.cloudflare.com/pages/get-started/direct-upload/
https://developers.cloudflare.com/pages/framework-guides/deploy-anything/

B. 기존 웹호스팅 / Nginx / Apache

index.html과 나머지 파일을 웹서버가 공개하는 문서 폴더에 그대로 복사합니다.
예를 들어 https://example.com/ 또는 https://example.com/lukory/ 경로에 올릴 수 있습니다.
이미지·폰트·스크립트는 상대 경로를 사용하므로 하위 폴더 배포도 가능합니다.
단일 문서와 #feed 앵커를 사용하므로 클라이언트 라우팅용 rewrite 규칙이 필요하지 않습니다.

C. GitHub Pages

저장소의 공개 대상 폴더에 이 패키지의 내용을 넣고, 그 폴더를 Pages 배포 대상으로 지정합니다.
패키지에는 .nojekyll 파일도 들어 있습니다.

6. 로컬에서 HTTP로 확인하기 (선택)

파일 더블클릭으로도 실행되지만, 배포와 같은 HTTP 환경에서 확인하려면
Python이 설치된 컴퓨터에서 사이트 폴더를 연 뒤 다음 명령을 실행합니다.

python3 -m http.server 8080

Windows 환경에 따라 아래 명령을 사용합니다.

py -m http.server 8080

그다음 브라우저에서 http://localhost:8080/ 을 엽니다.
이 명령은 로컬 확인용이며, 공용 인터넷에 배포하는 명령은 아닙니다.

7. 파일별 수정 위치

index.html
  사이트 제목, 소개 문구, 메인 질문 카드, 메뉴, 피드 도구, 푸터.

styles.css
  색상, 글꼴, 크기, 여백, 카드, 질문·상세 모달, 반응형 규칙, 애니메이션.
  상단 :root의 --orange, --ink, --paper 변수를 바꾸면 주요 색상을 조정할 수 있습니다.

data.js
  moods: 분위기 종류와 결과 제목.
  questionGroups: 질문, 변형 문장, 답변 선택지.
  portraits: 여섯 이미지의 설명과 답변 매칭 점수 기준.
  faces: 샘플 게시물, 닉네임, 댓글, 반응 수.

app.js
  startStudio / renderQuestion: 질문 흐름.
  matchPortrait / generateResult: 로컬 얼굴 선택과 결과 준비 상태.
  renderResult / publishResult: 결과 표시와 로컬 게시.
  renderFeed / openFace: 목록과 상세 화면.
  renderComments / deleteComment: 댓글 표시와 삭제.
  readState / persist: 입력 검증과 브라우저 저장.

assets/faces-editorial-contact-sheet.png
  이 사이트를 위해 AI로 만든 3열 × 2행의 가상 인물 이미지입니다.
  CSS의 background-position으로 각각의 얼굴을 표시합니다.

assets/lukory-sans.woff2
  Noto Sans KR 가변 글꼴을 한글·라틴 문자 중심으로 경량화한 로컬 글꼴입니다.
  CSS 글꼴 이름은 LukorySans입니다.
  글꼴 라이선스는 같은 폴더의 OFL-NotoSansKR.txt에 있습니다.

8. 이후 실제 서비스로 연결할 지점

현재 화면을 유지하면서 아래 세 지점에 서버 API를 연결하면 됩니다.

1) 질문 생성
   questionGroups를 읽는 부분을 서버의 질문 생성 응답으로 교체합니다.
   질문 ID와 답변 ID를 함께 관리하고, 로딩·실패·재시도 상태를 추가합니다.

2) 이미지 생성
   generateResult의 샘플 매칭을 이미지 생성 작업 요청으로 교체합니다.
   현재 1.5초의 데모 전환 대신 실제 작업의 진행·실패·완료 상태를 사용합니다.
   생성된 개별 이미지 URL을 받도록 portraitHTML과 관련 데이터 필드를 확장합니다.
   모델 API 키는 브라우저 파일에 넣지 않고 서버 환경변수로 관리합니다.

3) 게시물·댓글 공유
   readState/persist의 브라우저 저장을 게시물·댓글·반응 API로 교체합니다.
   실제 작성자 식별, 수정·삭제 권한, 중복 반응 제어는 서버가 담당해야 합니다.
   서버 저장 성공 후 화면에 반영하도록 바꾸고, '이 기기' 데모 안내를 함께 업데이트합니다.

9. 확인한 항목

메인 화면 → 첫 답변 → 2~5번째 질문 → 결과 → 데모 게시 → 상세 → 댓글 → 좋아요·투표를
브라우저에서 실행했습니다. 새로고침 후 저장한 항목이 유지되는 것도 확인했습니다.
HTML 태그를 입력한 댓글이 실행되지 않고 문자로 표시되는지 확인했습니다.
모바일·태블릿 뷰포트에서 가로 넘침과 상세 화면을 확인했습니다.
모달 닫기 및 댓글 삭제 이후 키보드 초점 처리를 확인했습니다.
질문 답변의 1,024가지 조합에서 유효한 결과가 나오고, 여섯 얼굴에 모두 도달하며,
첫 선택의 분위기가 유지됨을 로컬 검증했습니다.
잘못 저장된 ID·날짜를 방어하며, JS 문법과 로컬 파일 경로를 검증했습니다.

실제 AI API, 사용자 간 데이터 공유, 회원 인증, 실서비스 운영 부하 검증은
이번 백엔드 없는 패키지의 범위에 포함되지 않습니다.

10. 기술적 구성

HTML5 + CSS + 일반 JavaScript. 프레임워크 런타임이나 외부 CDN을 사용하지 않습니다.
실행에 필요한 이미지와 한글 글꼴이 패키지 안에 들어 있습니다.
API 호출, 분석 추적, 광고 스크립트, 업로드, 로그인은 없습니다.
최신 Chrome, Edge, Firefox, Safari의 표준 기능을 사용합니다.
WebMCP가 지원되는 브라우저에서는 얼굴 목록 읽기·상세 열기·질문 시작 도구를
점진적 기능 향상으로 등록하며, 지원하지 않는 브라우저에서는 건너뜁니다.
이번 검증 브라우저에서는 WebMCP를 사용할 수 없어 해당 도구의 실행 검증은 하지 않았습니다.
